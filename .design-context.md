# VibeBass design context

## Brief

- Mode: Redesign / Overhaul, explicitly requested on 2026-09-12.
- Product: Korean-language PDF score and YouTube practice workspace for bass players.
- Audience: musicians repeatedly reading a score, recording sync points, and revisiting saved sessions.
- Assumptions: Korean first; WCAG AA target; existing Kotlin/Compose and browser media bridge retained. No build or compilation authorized.
- Brand: retain the VibeBass Studio name. Practical, calm, tactile. The score is the primary content.

## Redesign Audit

- Current: neon green and violet on near-black, gradient monogram, dense nested cards, 9-12px controls, fixed 38/62 split.
- Flow: choose a local PDF, match YouTube, record anchors, save, reopen from the song list.
- Keep: route `/`, product name, local file selection, video playback, automatic matching, sync editing, saved songs and API contracts.
- Retire: artificial sample anchors/video, decorative LP placeholders, tiny DEL actions, fixed DOM percentages, extreme z-index values, unattached LazyListState used as PDF position.
- No marketing pages, analytics contracts, legal copy, or SEO route migration were found in this screen. Keep the VibeBass title and set document language to Korean.

## Section specification

1. Header: 64px, retained wordmark, concise practice status. Single line on compact widths.
2. Session heading: title and PDF selection; concise file state, no invented metadata.
3. Controls: real video, visible time, practice/sync mode, sync-point or saved-song tab. Lists scroll independently; save action remains reachable.
4. Score: largest pane, compact toolbar, calm empty state with upload action; real PDF is the only score imagery.
5. Compact screens: score and controls use explicit tabs with persistent state. Hidden media must not obscure visible controls.
6. Feedback: inline save/load/error state outside DOM media bounds. Loading, empty, selected, saving, success and failure states are distinct.
